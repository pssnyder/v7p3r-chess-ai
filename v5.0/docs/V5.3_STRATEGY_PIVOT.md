- Only 323k positions for 953k parameters (0.34 samples/param)

**Strategic Pivot:** Change optimization target from "predict exact grade" to "predict good moves"

**New Approach:** Multi-engine data collection focused on V7P3R character and puzzle-solving

## The Paradigm Shift

### ❌ OLD STRATEGY (v5.1, v5.2)

**Goal:** Balanced accuracy across all 6 grades (0-5)

**Problem:** Grades 3-5 are "what not to do" - they're training signal but not deployment goals

**Result:** 45% exact grade accuracy, but model doesn't prefer good moves

### ✅ NEW STRATEGY (v5.3+)

**Goal:** Maximize "Good Move Rate" - % of predictions in grades 0-2

**Rationale:**
- Chess engines need to CHAIN good moves to win
- A model that predicts grade 2 when truth is grade 0 is still useful
- A model that predicts grade 3 when truth is grade 0 is dangerous

**Success Criteria:**
```
Primary:   Good Move Rate >70% (predictions in grades 0-2)
Secondary: Excellent Move Rate >40% (predictions in grades 0-1)
Tertiary:  Bad Avoidance >85% (predictions NOT in grades 4-5)
```

## Multi-Engine Data Collection Strategy

### Why Multiple V7P3R Versions?

**V7P3R has evolving "character"** across versions:
- v17.1: Stable defensive style
- v18.0: Aggressive tactical play
- v18.3: Balanced opening book integration
- v18.4: Latest refinements

**Collecting data from all versions:**
1. Captures V7P3R's evolving playstyle
2. Provides diversity in move selection
3. Shows what V7P3R ACTUALLY plays (not just Stockfish optimal)
4. Enables AI to learn "engine character" not just "perfect play"

### Why Puzzles Instead of Games?

**Puzzles provide superior training data:**

| Feature | Puzzles | Games |
|---------|---------|-------|
| **Move quality labels** | ✅ Solution provided | ❌ Need Stockfish analysis |
| **Tactical density** | ✅ Every position is critical | ⚠️ Many quiet moves |
| **Stockfish grading** | ✅ Fast (compare to solution) | ⚠️ Slow (need full analysis) |
| **Sequence data** | ✅ Multi-move combinations | ✅ Full game continuations |
| **Volume available** | ✅ 4M Lichess puzzles | ⚠️ 15k V7P3R games |
| **Rating distribution** | ✅ Balanced 1500-2500 | ⚠️ V7P3R-specific ELO |

**Result:** Puzzles give us 20x more tactical training data in 1/10th the processing time

### Why Include C0BR4?

**C0BR4 is V7P3R's "cousin":**
- Both written by same developer
- Similar evaluation philosophy (heuristic-based)
- Different implementation (C# vs Python)
- More game data (10k vs 5k)
- Different tactical preferences

**Cross-engine learning:**
- Learn common patterns between engines
- Identify V7P3R-unique traits
- Increase data diversity
- Improve generalization

## New Evaluation Metrics

### Primary: Good Move Rate

```python
# % of predictions in grades 0-2
good_predictions = np.sum(predictions <= 2)
good_move_rate = (good_predictions / total) * 100

Target: >70%
v5.1 Baseline: ~51% (calculated retroactively)
```

### Secondary: Excellent Move Rate

```python
# % of predictions in grades 0-1
excellent_predictions = np.sum(predictions <= 1)
excellent_move_rate = (excellent_predictions / total) * 100

Target: >40%
v5.1 Baseline: ~28%
```

### Tertiary: Bad Avoidance

```python
# % of predictions NOT in grades 4-5
non_bad_predictions = np.sum(predictions <= 3)
bad_avoidance_rate = (non_bad_predictions / total) * 100

Target: >85%
v5.1 Baseline: ~62%
```

### Quality Metrics

- **Grade 0 Precision:** When predicting grade 0, how often correct?
- **Grade 0-2 Recall:** Of actual good moves, how many found?
- **Good Move Accuracy:** Accuracy within grades 0-2 only

## Training Strategy Changes

### Model Architecture: REVERT to v5.1

**Rationale:**
- v5.2 (wider) showed NO benefit with current data
- Save 950k param model for when we have >1M samples
- v5.1 is faster and equally effective

**Config:**
```yaml
shared_dims: [256, 256, 128, 64]  # Back to v5.1
policy_hidden: 64
value_hidden: 32
```

### Loss Function: Add Good Move Bonus (NEW!)

**Current:** CrossEntropyLoss (all grades equal weight)

**Proposed:**
```python
# Custom loss that rewards predicting good moves
def good_move_loss(predictions, targets):
    ce_loss = CrossEntropyLoss()(predictions, targets)
    
    # Bonus for predicting grades 0-2 (even if wrong exact grade)
    predicted_classes = torch.argmax(predictions, dim=1)
    good_predictions = (predicted_classes <= 2).float()
    good_targets = (targets <= 2).float()
    
    good_accuracy = (good_predictions * good_targets).mean()
    good_bonus = -0.5 * good_accuracy  # Negative = reward
    
    return ce_loss + good_bonus
```

### Class Weights: Refined

**Old weights:** [1.0, 5.0, 3.5, 2.5, 1.8, 1.0]

**New weights (after oversampling):**
```python
# After balancing, reduce extreme weights
class_weights = [1.0, 2.0, 1.5, 1.5, 1.5, 1.0]
```

Oversampling handles distribution, weights fine-tune.

## Self-Evaluation Loop (Future Phase)

**Concept:** AI model solves puzzles, feeds its own training

**Process:**
1. Current v5.1 model solves 10k puzzles
2. Record its move choices
3. Stockfish grades AI moves
4. Feed back into training
5. **Iterate:** New model solves same puzzles better

**Benefits:**
- Bootstrapping improvement
- Identifies model weaknesses
- Creates adversarial training data
- Continuous learning loop

**Timeline:** After v5.3 reaches >50% accuracy

## Philosophical Shift

**Old Thinking:**
> "The model must predict exactly which of 6 grades a move belongs to"

**New Thinking:**
> "The model must preferentially suggest good moves (0-2) and avoid bad ones (4-5)"

**Why This Matters:**
- Chess is about chaining good moves, not predicting perfect labels
- A model that says "this is a good move" (even if off by 1 grade) is useful
- A model that says "this is the 6th best move" when it's actually 5th is useless

**Result:** Training optimizes for what actually matters - move quality bias, not label precision.
