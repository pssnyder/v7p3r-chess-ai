Value MAE
?
📏 Mean Absolute Error (MAE)
What it is: The average magnitude of errors in position evaluation, measured in the [-1, 1] range.
MAE = (1/n) × Σ|predicted - actual|
In Chess Terms: MAE of 0.1039 ≈ 1,039 centipawns error on average. That's roughly equal to 1 pawn in evaluation accuracy.
Why MAE not MSE? MAE is more robust to outliers (like mate positions) and gives equal weight to all errors. MSE (squared errors) would punish big mistakes more heavily.

Validation Loss
?
📉 Validation Loss (Combined)
What it is: A combined measure of how well the model performs on data it hasn't seen during training.
Val Loss = Policy Loss + 0.1 × Value Loss
Why Validation? Training loss can be misleading - a model can "memorize" the training data. Validation loss shows true generalization ability.
What's good? Lower is better. If val loss decreases with train loss, the model is learning patterns (not memorizing). If val loss increases while train loss decreases, that's overfitting!

Cross-Entropy Loss
?
🔢 Cross-Entropy Loss (Classification)
What it is: Measures how well predicted probabilities match true labels for classification problems.
CE = -Σ(y_true × log(y_pred))
Intuition: If the model is 90% confident about Grade 5 and it's correct, the loss is low. If it's 90% confident but wrong, the loss is high.
Why this loss? Perfect for multi-class problems (6 grades). It penalizes confident wrong answers more than uncertain ones, encouraging calibrated predictions.

Huber Loss
?
🛡️ Huber Loss (Robust Regression)
What it is: A loss function that's less sensitive to outliers than MSE (Mean Squared Error).
If |error| ≤ δ: use MSE
If |error| > δ: use MAE
(δ = 0.5 for us)
Why Huber? Mate positions can have extreme evaluations (+/-10,000cp). Huber Loss prevents these outliers from dominating training.
Trade-off: Combines MSE's smoothness for small errors with MAE's robustness for large errors. Best of both worlds!

δ = 0.5 (robust to outliers)

🎯 What These Metrics Mean
  • Policy Accuracy (47.56%): The model correctly predicts the exact move quality grade almost half the time after only 2 epochs. This is exceptional progress, nearly at the 50% target already.
  • Top-2 Accuracy (~75%): When allowing ±1 grade error, the model is accurate 3 out of 4 times. This means it understands move quality patterns very well - even "mistakes" are minor.

  • Loss Convergence: Both train and validation losses are decreasing steadily with no signs of overfitting
    ⚠️ Overfitting
    What it is: When a model "memorizes" the training data instead of learning general patterns.
    Signs of Overfitting:
    • Train loss ↓ but val loss ↑
    • High accuracy on training data, low on validation
    • Model performs great in testing, fails in real games
    Prevention: We use dropout (0.3), early stopping, and validation monitoring to avoid overfitting!
    . The model is learning effectively from the data.
  • Fast Learning: Jumping from 44.2% to 47.56% accuracy in a single epoch

    In our case:
    • 1 epoch = 184,742 positions
    • 722 batches (256 positions each)
    • Takes ~12.4 seconds on CPU
    Why multiple epochs? The model needs to see examples multiple times to learn patterns. Like studying flashcards repeatedly!

🚀 Recommended Next Steps
  1. Start Full Training (100 epochs): The quick test proves the pipeline works. Run the complete training to reach peak performance.
  2. Monitor for Overfitting: Watch the gap between train and validation loss. If val loss starts increasing while train loss decreases, consider increasing dropout
    🎲 Dropout
    What it is: Randomly "turns off" 30% of neurons during training to prevent overfitting.
    Analogy: Like studying with random parts of your notes covered - forces you to learn concepts, not memorize exact pages.
    Our setting: dropout=0.3 means each neuron has 30% chance of being ignored each training step. Prevents co-adaptation!
    or reducing model capacity.
  3. Early Stopping
    🛑 Early Stopping
    What it is: Automatically stops training when the model stops improving on validation data.
    Our setup:
    • Patience: 15 epochs
    • If val loss doesn't improve for 15 consecutive epochs → stop training
    • Prevents wasting time on saturated learning
    Why? Training too long can cause overfitting. Early stopping finds the "sweet spot" automatically!
    :     The trainer will automatically stop if validation loss doesn't improve for 15 epochs. This prevents wasting compute on saturated learning.
  4. Learning Rate Scheduling
    📉 Learning Rate Scheduling
    What it is: Automatically adjusts how fast the model learns based on progress.
    Start: LR = 0.001
    If stuck for 5 epochs: LR × 0.5
    Minimum: LR = 0.000001
    Analogy: When learning a new skill, you start with big steps. As you get better, you make smaller refinements. Same here!
    Strategy: ReduceLROnPlateau monitors val loss. If it plateaus, lower the learning rate to fine-tune the model.
    :     If loss plateaus, the ReduceLROnPlateau scheduler will automatically lower the learning rate to fine-tune the model.
  5. Evaluate on Test Set
    🧪 Test Set (Hold-out Data)
    What it is: Data the model has NEVER seen during training or validation.
    Our split:
    • Training: 184,742 positions (80%)
    • Validation: 23,089 positions (10%)
    • Test: 23,099 positions (10%)
    Why separate? Validation guides training. Test measures TRUE generalization - how well the model works on completely new data!
    :     After training completes, run the evaluation script on the held-out test set (23,099 positions) to measure true generalization.
