# V7P3R AI v5.1 - Full Pipeline Guide

This document outlines the complete end-to-end workflow from feature expansion to model training.

## Overview

**Goal:** Expand features from 26 to 92+ to fix binary classification problem and improve policy accuracy from 49% to 54%+.

**Key Changes:**
- **Phase 1A**: Added 60 tactical/structural features (pins, forks, rook placement, etc.)
- **Phase 1B**: Added 15 multi-move context features (top-5 Stockfish evals) - **CRITICAL**
- **Class weights**: Force model to learn rare grades (1-4)
- **Expected improvement**: 49% → 54%+ accuracy with proper grade distribution

## Troubleshooting

### Feature recalculation fails

**Symptom:** Python error during `calculate_features.py`

**Diagnosis:**
1. Check input file exists: `data/final/v7p3r_ai_v5_training_dataset_complete.jsonl`
2. Verify first record has required blocks: `metadata`, `position`, `engine_decision`, `stockfish_analysis`
3. Check disk space (output file will be ~100 MB)

**Fix:** Ensure input file is the original v5.0 master dataset (with Stockfish multipv=5 analysis)

### Preprocessing dimension mismatch

**Symptom:** `ValueError: Feature count mismatch`

**Diagnosis:** Input splits have v5.0 features (26) instead of v5.1 features (92+)

**Fix:** Verify you're using splits_v5.1 directory (generated from v5.1 expanded features):
```powershell
$record = Get-Content data\analysis\splits_v5.1\train.jsonl -First 1 | ConvertFrom-Json
$record.features | Get-Member -MemberType NoteProperty | Measure-Object
# Should show ~92 features, not 21-26
```

### Model initialization fails

**Symptom:** `RuntimeError: Input dimension mismatch`

**Diagnosis:** `input_dim` in `src/model.py` doesn't match preprocessed feature count

**Fix:** Update `input_dim` to match `preprocessing_stats.json` → `total_features`

### Training accuracy stuck at 49%

**Symptom:** Validation accuracy plateaus at ~49% (same as v5.0)

**Diagnosis:** Class weights not applied or features not expanded

**Fix:**
1. Verify `src/train.py` line ~150 has class weights: `torch.tensor([1.0, 5.0, 3.5, 2.5, 1.8, 1.0])`
2. Verify preprocessing used v5.1 splits (92+ features)
3. Check `preprocessing_stats.json` → `total_features` is >90

### Binary classification persists

**Symptom:** Confusion matrix still shows only grades 0 and 5 predicted

**Diagnosis:** Multi-move context features (F100-F114) not calculated

**Fix:** Verify expanded features contain F100-F114:
```powershell
$record = Get-Content data\analysis\splits_v5.1\train.jsonl -First 1 | ConvertFrom-Json
$record.features.F100_best_move_eval_cp  # Should exist
$record.features.F114_alternative_move_quality  # Should exist
```

If missing, re-run feature recalculation with `--feature-set standard` flag.
