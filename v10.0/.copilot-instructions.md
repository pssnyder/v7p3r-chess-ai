## 12. FAQ: What NOT to Do

### ❌ "Copilot, review my entire codebase"
**Why it's bad**: Forces 20+ file reads, searches, analysis.  
**Better approach**: You review specific file (open in VS Code), ask Copilot for 1 fix.

### ❌ "Can you refactor src/ for me?"
**Why it's bad**: Ambiguous scope, multiple files, unknown impact.  
**Better approach**: "Refactor src/accumulator_architecture.py to [specific goal]".

### ❌ "Implement the entire Sprint 2 for me"
**Why it's bad**: 5+ files, 100+ tool calls, doesn't build your understanding.  
**Better approach**: Do 1 file per session, ask for help on blockers.

### ❌ "What should I implement next?"
**Why it's bad**: Requires reading dev plan, suggesting options, discussion.  
**Better approach**: You read the dev plan, choose next file, tell Copilot exactly what.

### ❌ "Run these tests for me"
**Why it's bad**: Wastes terminal tool calls.  
**Better approach**: You run tests locally (Ctrl+` opens VS Code terminal), show results if error.

## 14. Emergency Contacts (When Everything Breaks)

If something fails:

1. **SyntaxError**: VS Code shows line number, copy/paste error message
2. **Import Error**: File in wrong place or missing dependency
3. **Test Failure**: Run locally, see output, paste error to Copilot
4. **Performance Issue**: Profile locally (time.time()), show results
5. **Logic Bug**: Write minimal reproducible example (5 lines), show test

**Never ask**: "The code doesn't work, fix it"  
**Instead ask**: "I ran [command], got [error], code is [paste], fix it"
